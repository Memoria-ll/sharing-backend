# 手動実機チェックリスト（backend）

自動テスト（`node --test`）では担保できない、実際の HTTP エンドポイントを介した検証項目。
設計書 `.tmp-design-dynamic-modules.md` §8 V11〜V14 に対応する。

| # | 手順 | 期待結果 | 赤なら疑うもの |
|---|---|---|---|
| V11 | `ModuleB: 3` を含む1件を HTTP save（POST）→ 返った `id` で HTTP get（GET） | レスポンスの `characters[0]` に `moduleB: 3` が含まれる | `moduleB` が無い → 走査が効いていない。400 が返る → パターンかバリデーションの誤り |
| V12 | 旧4モジュール形式（`ModuleX/Y/D/A` のみ）の1件を POST → GET | `moduleX/Y/D/A` の4キーのみが保存され、値は送信どおり | キーが増減している → ユニオン仕様の誤り |
| V13 | `ModuleXY: 2` を含む1件を POST → GET | `moduleXY: 2` が保存されている | 保存されていない → 接尾辞パターンが1文字のままで追加制約2が効いていない |
| V14 | 21種類の異なるモジュール接尾辞を含む1件を POST | HTTP **400**、レスポンスボディが `{"error":"モジュール種別は20種類以内にしてください"}` | 200 が返る → `MAX_MODULE_COUNT` が効いておらず増幅経路が開いたまま |
